# 密钥泄露检测与处置 Playbook

> 密钥一旦进过 Git 历史，就必须**假定已泄露**——即使仓库是私有的、即使你立刻 force push 删掉了。
>
> 参考：`github/awesome-copilot@secret-scanning`（4.2K 安装）、
> `ghostsecurity/skills@ghost-scan-secrets`（3K 安装）。
> 本篇写扫描器不会告诉你的部分：**扫到之后怎么办**，以及怎么把假阳性压下去。

## 1. 泄露响应：顺序错了等于没做

发现硬编码密钥后，很多人第一反应是"把它从代码里删掉再 commit"。
**这是错的**——密钥仍在 Git 历史里，而你浪费了最宝贵的几分钟。

正确顺序（严格按此执行）：

```
① 轮换（Rotate）   —— 签发新密钥，让旧的失效。最优先，因为它立刻止血
② 撤销（Revoke）   —— 显式吊销旧密钥，别只是"不再使用"
③ 排查（Investigate）—— 查旧密钥的调用日志，确认有无异常使用
④ 清理（Purge）    —— 从代码与 Git 历史中移除
⑤ 加固（Prevent）  —— 加 pre-commit / CI 门禁，防止再次发生
```

**为什么轮换排第一**：清理 Git 历史需要改写提交、通知所有协作者重新 clone，
可能耗时数小时；而轮换通常只要几分钟。在这几小时里，旧密钥如果还有效，就一直是敞开的门。

### 各类密钥的轮换要点

| 类型 | 轮换动作 | 易忽略的地方 |
|------|---------|-------------|
| 云厂商 AK/SK | 建新 key → 更新配置 → 删旧 key | 别只是禁用，要删除；检查是否有其他服务在用同一把 |
| 数据库密码 | 改密码 → 滚动重启应用 | 连接池会持有旧连接；检查备份脚本、BI 工具、定时任务 |
| OAuth Client Secret | 平台生成新 secret | 多环境共用同一 client 时会一起挂，先确认使用范围 |
| API Token（GitHub/Slack 等） | 平台吊销 + 新建 | CI secrets、本地 `.env`、队友机器上都可能有副本 |
| 私钥 / 证书 | 生成新密钥对 + 重签 | 已签发的旧签名不会自动失效，需要额外的吊销机制 |
| JWT 签名密钥 | 换 key + 支持双 key 校验过渡 | 直接换会让所有在线用户掉线，需灰度 |

### 排查阶段该查什么

```bash
# 云厂商：查该 AK 的调用记录（是否有陌生 IP / 异常地域 / 异常 API）
# GitHub Token：Settings → Security log
# 关键判断：泄露窗口期内，有没有来自非本方基础设施的调用
```

泄露窗口 = 密钥进入历史的那个 commit 时间 → 轮换完成时间。
仓库公开过的，窗口内**必须假定已被自动化爬虫抓走**（公开仓库的密钥通常在几分钟内被扫走）。

## 2. Git 历史清理：三种方式与代价

| 方式 | 适用 | 代价 |
|------|------|------|
| **只在最新 commit** → `git commit --amend` | 还没 push | 无 |
| **在近几个 commit** → 交互式 rebase | 已 push 但分支只有自己在用 | 需要 force push，协作者要重新拉取 |
| **在很早的历史里** → `git filter-repo` | 密钥藏在几百个 commit 之前 | 全仓库 hash 改写，所有人必须重新 clone；PR、tag、CI 缓存都受影响 |

```bash
# 推荐工具（BFG 与 filter-branch 的替代品，官方推荐）
pip install git-filter-repo
git filter-repo --replace-text <(echo 'AKIA0123456789ABCDEF==>REDACTED')
```

> **重要**：清理历史后，GitHub 上仍可能通过 commit hash 直接访问旧对象，
> 需要联系平台方 GC，或者更彻底的做法是**删库重建**。
> 这也是为什么第 ① 步轮换不可跳过——历史清理从来不是可靠的止血手段。

**判断要不要清理历史**：密钥已轮换且确认无异常使用 → 清理是"卫生"而非"止血"，
可以排期做；如果密钥无法轮换（例如第三方给的固定凭据），才是必须立刻清理。

## 3. 假阳性压制：扫描器噪声是最大的落地障碍

扫到 300 条告警但 295 条是假的，团队三天后就会关掉这个检查。
压噪声的三个手段，按性价比排序：

### 手段一：熵 + 上下文双条件

单看正则匹配会把 `password = "password"`、`api_key = "your-api-key-here"` 全报出来。
加上 **Shannon 熵阈值**（真实密钥通常 > 3.5 bits/char）可以滤掉大部分占位符。

`scripts/secret_scan.py` 已内置这个逻辑：正则命中 + 熵阈值 + 占位符词表三重过滤。

### 手段二：路径排除清单

固定排除（本库脚本已默认排除）：

```
测试固件：test/、tests/、__tests__/、fixtures/、mock/、*.spec.*、*.test.*
文档示例：docs/、examples/、README、CHANGELOG
依赖与产物：node_modules/、vendor/、dist/、build/、.venv/
锁文件：package-lock.json、yarn.lock、poetry.lock（里面的 hash 会触发高熵）
```

> 注意：排除 `test/` 是**权衡**，不是安全做法。测试目录里放真实密钥的事故很常见。
> 折中方案是对测试目录降级为 warning 而不是完全跳过。

### 手段三：基线文件（baseline）

存量仓库第一次扫描必然一堆历史遗留。做法是：
第一次扫描结果全部记入基线（含文件+行号+指纹），之后**只报新增的**。
这样门禁可以立刻上线，存量问题另行排期，不会因为"修不完"而永远不开门禁。

## 4. 预防：三道防线

```
第一道：本地 pre-commit hook   → 最快反馈，但可被 --no-verify 绕过
第二道：CI 门禁（PR 阻断）      → 不可绕过，是真正的防线
第三道：平台侧扫描（推送保护）   → 兜底，覆盖直推与其他客户端
```

**三道都要有，但只有第二道是刚性的。** 第一道是为了不让开发浪费一次 CI 等待，
第三道是为了覆盖绕过 CI 的路径。

CI 集成模板见 `assets/secret-scan-ci.yml`，核心是：

```yaml
# 只扫本次 PR 的改动范围，全量扫描放在定时任务里
- run: git fetch origin ${{ github.base_ref }} --depth=1
- run: python3 scripts/secret_scan.py $(git diff --name-only origin/${{ github.base_ref }}...HEAD) --strict
```

## 5. 从根上少产生密钥

能不用长期密钥就不用。按优先级：

1. **OIDC / Workload Identity**（CI 与云之间）—— 短期令牌，无长期凭据可泄露
2. **托管身份**（云上服务访问云上资源）—— 完全无凭据
3. **密钥管理服务**（Vault / KMS / Secrets Manager）—— 集中管理 + 自动轮换 + 审计
4. **环境变量注入**（部署时注入，不落盘）—— 底线做法
5. **`.env` 文件 + `.gitignore`** —— 只适合本地开发，且 `.gitignore` 会被 `git add -f` 绕过

> `.env` 加进 `.gitignore` 不是密钥管理方案，它只是防止**手滑**。

## 6. 常见坑

| 坑 | 后果 | 规避 |
|----|------|------|
| 删了代码里的密钥就以为安全了 | 历史里仍在，且未轮换 | 永远先轮换 |
| 私有仓库放松警惕 | 仓库可能被转公开、成员流动、fork 泄露 | 私有仓库同等对待 |
| 只扫源码不扫配置与 CI | `.yml`、`.tf`、`Dockerfile`、`k8s` manifest 是重灾区 | 扫全部文本文件类型 |
| 只扫当前文件不扫历史 | 存量泄露完全看不见 | 首次接入时做一次全历史扫描 |
| 把密钥写进容器镜像层 | 即使后续层删掉，镜像层里仍可提取 | 用 BuildKit `--mount=type=secret` |
| 密钥打进前端 bundle | 任何用户都能看到 | 前端不放任何服务端密钥，走后端代理 |
| 日志里打印完整 token | 日志系统成为二次泄露源 | 日志脱敏中间件，只打前 4 后 4 位 |
| 轮换后忘了更新所有消费方 | 服务半夜挂掉 | 轮换前先列出全部使用方清单 |

## 7. 检查清单

**发现泄露时**：

- [ ] 已轮换新密钥并生效（第一优先，不要先删代码）
- [ ] 已显式吊销旧密钥（不是仅停用）
- [ ] 已查泄露窗口期内的调用日志，确认有无异常使用
- [ ] 已确认全部消费方都切到新密钥（CI、其他服务、本地开发、定时任务）
- [ ] Git 历史清理已完成或已明确排期
- [ ] 已记录事件（时间线、影响范围、处置动作）

**日常防护**：

- [ ] CI 有阻断级密钥扫描门禁（不只是 warning）
- [ ] 首次接入时做过一次全 Git 历史扫描
- [ ] 有基线文件机制，存量问题不阻塞门禁上线
- [ ] `.gitignore` 覆盖 `.env*`、`*.pem`、`*.key`、`*credentials*`
- [ ] 生产密钥来自 KMS / OIDC，而非环境变量硬编码
- [ ] 日志有脱敏，token 与密码不会被完整打印
- [ ] 容器镜像内无密钥（用 `--mount=type=secret` 构建）
